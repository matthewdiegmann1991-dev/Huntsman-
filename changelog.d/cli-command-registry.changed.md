- The binary's commands are declared once, in `src/cli/commands.rs`: each command's name, general-help summary, usage synopsis and handler. The dispatcher, the general help and the usage line are read from that table, where before they were three hand-kept lists that had to agree (adding a command meant editing all three, plus its help). The usage line is still one compile-time literal (`concat!` in the registry macro), so the release workflow's identity probe, which greps the published binary's bytes for it, keeps working; `tests/release_ci.rs` now checks the built binary holds that literal. Every help and usage output is byte-identical to before except the usage line, whose alternatives now follow the general help's order (`osint`, `security-tools`, `query` and `research` moved); the dispatch mapping of all 67 commands is unchanged. The registry's tests hold that each command is declared once, has its own `--help`, appears once in the help, and owns its usage alternatives; `tests/cli_surface.rs` and `tests/architecture_doc.rs` read commands from the registry. `serve`'s people-discovery and research adapters share one error mapping (`adapter_error`).
